# رسائلي — تطبيق مراسلة ومكالمات بخادم خاص

تطبيق ويب للمراسلة النصية والمكالمات الصوتية والمرئية: تسجيل ودخول باسم مستخدم وكلمة مرور،
دليل مستخدمين، محادثات تُحفظ على الخادم وتُسلَّم لحظياً بين **أجهزة مختلفة** عبر
WebSocket، مع حالة «متصل الآن» وعدّادات غير المقروء وعلامات (أُرسلت / تم التسليم / مقروءة).
الواجهة عربية RTL ومتجاوبة مع الجوال، مع PWA manifest.

## بنية المشروع

```
server.js          الخادم: واجهة ثابتة + REST API + WebSocket على نفس المنفذ
store.js           طبقة التخزين (وحدة واحدة — انظر «قاعدة البيانات» أدناه)
public/            الواجهة (index.html + app.js + styles.css + manifest)
test/e2e.mjs       اختبار شامل آلي (npm test)
render.yaml        إعدادات النشر على Render
data/              ملف البيانات data.json (يُنشأ تلقائياً، غير مرفوع لـ Git)
```

- المنفذ: `process.env.PORT` (افتراضي 3000) — الخادم والواجهة على نفس المنفذ والرابط.
- كلمات المرور: مُجزّأة بـ `scrypt` من مكتبة Node المدمجة، وجلسات الدخول رموز عشوائية.

## التشغيل محلياً

```bash
npm install
npm start
```

ثم افتح: http://localhost:3000

للتجربة من جهازين على نفس الشبكة: افتح `http://<IP-جهازك>:3000` من الجوال،
أو افتح متصفحين/نافذتين وسجّل باسمين مختلفين.

## الاختبار الآلي

```bash
npm test
```

يشغّل خادماً مؤقتاً ويتحقق من: التسجيل، رفض الاسم المكرر وكلمة المرور الخاطئة،
الإرسال اللحظي عبر WebSocket، سجل المحادثة، إشعار القراءة، وحفظ رسالة أُرسلت
أثناء غياب المستقبِل وظهورها بعد عودته، إضافة إلى إشارات المكالمات (دعوة/قبول/رفض/
عرض وجواب SDP ومرشحات ICE/إنهاء) وسجلّات المكالمات وحالة «غير متاح» للمستخدم غير المتصل.

## المكالمات الصوتية والمرئية (WebRTC)

- من ترويسة أي محادثة: زر 📞 لمكالمة صوتية وزر 📹 لمكالمة فيديو، مع واجهة للمكالمة
  الصادرة («جارٍ الاتصال…») والواردة (قبول/رفض مع نغمة رنين) والجارية (مؤقّت مباشر،
  كتم الميكروفون، تشغيل/إيقاف الكاميرا، إنهاء). في مكالمات الفيديو يظهر الطرف الآخر
  بملء الشاشة وفيديوهك صغيراً في الزاوية (Picture-in-Picture).
- **الإشارة (Signaling):** تمر عبر WebSocket الخادم نفسه بين الطرفين فقط بأنواع
  الرسائل: `call_invite` و`call_accept` و`call_reject` و`call_offer` و`call_answer`
  و`call_ice` و`call_end`. الخادم يتتبّع حالة كل مكالمة: إذا كان الطرف الآخر غير
  متصل يرجع للمتصل `call_unavailable`، وإذا كان في مكالمة أخرى يرجع `call_busy`،
  ويُنهي الحالة تلقائياً عند انقطاع اتصال أحد الطرفين.
- **الوسائط نفسها (الصوت/الفيديو) لا تمر عبر الخادم إطلاقاً** — تنتقل مباشرة بين
  المتصفحين (Peer-to-Peer) عبر `RTCPeerConnection`، والخادم لا يخزّن أي SDP أو ICE.
- **اكتشاف العناوين (STUN):** تُستخدم خوادم Google العامة
  (`stun:stun.l.google.com:19302` و`stun:stun1.l.google.com:19302`) لاكتشاف
  العنوان العام خلف NAT.
- **سجل المكالمات:** عند انتهاء أي مكالمة (أو رفضها أو فواتها) يُحفظ سجل واحد في
  سجل المحادثة كرسالة من نوع `kind: "call"` تظهر كصفّ نظامي في المنتصف، مثل
  «📞 مكالمة صوتية — 02:35» أو «📹 مكالمة فيديو فائتة» أو «مكالمة مرفوضة»،
  ويُستخدم كمعاينة للمحادثة إذا كان الأحدث.
- **ملاحظة صادقة عن TURN:** بعض الشبكات الصارمة (NAT متماثل أو جدران نارية
  مؤسسية) قد تمنع الاتصال المباشر بين الطرفين، وعندها تحتاج المكالمة إلى خادم
  **TURN** وسيط لتمرير الوسائط. النسخة الحالية (v1) لا تتضمن TURN — يعمل الاتصال
  على أغلب الشبكات المنزلية وشبكات الجوال، ويمكن إضافة TURN لاحقاً عند الحاجة.

## النشر على Render عبر GitHub (خطوة بخطوة)

1. أنشئ حساباً على GitHub وارفع هذا المشروع إلى مستودع (Repository) جديد.
2. أنشئ حساباً على Render.com وسجّل الدخول.
3. من لوحة Render: **New +** ← **Blueprint** ← اختر المستودع — سيقرأ Render ملف
   `render.yaml` وينشئ خدمة الويب تلقائياً. (أو يدوياً: **New +** ← **Web Service**
   ← ربط المستودع ← Build Command: `npm install` ← Start Command: `npm start`
   ← Plan: Free.)
4. انتظر انتهاء أول نشر، وسيعطيك Render رابطاً مثل:
   `https://messages-app.onrender.com`
5. افتح الرابط من أي جهاز، أنشئ حساباً، وجرّب المراسلة بين جهازين مختلفين.

### حدود الخطة المجانية في Render — مهم

- **الخادم ينام** بعد 15 دقيقة بدون حركة، وأول طلب بعده يحتاج نحو دقيقة ليصحو.
- **نظام الملفات مؤقت (ephemeral):** أي ملفات تُكتب أثناء التشغيل — ومنها
  `data/data.json` الذي يحمل المستخدمين والرسائل — **تُمسح عند كل إعادة تشغيل
  أو إعادة نشر**. أي أن البيانات على الخطة المجانية مؤقتة وتناسب التجربة فقط.

### لجعل البيانات دائمة (عند الإطلاق الفعلي)

اختر واحداً:
- الترقية لخطة مدفوعة في Render + إضافة **Persistent Disk** وتركيبه على مجلد
  البيانات وضبط `DATA_DIR` عليه، أو
- الانتقال لقاعدة بيانات **Postgres**: طبقة التخزين كلها في `store.js`،
  فاستبدال هذه الوحدة وحدها بنسخة Postgres يكفي دون تغيير بقية الخادم.

## إضافة دومين خاص لاحقاً

1. اشترِ الدومين من أي مسجّل (مثل Cloudflare Registrar أو Namecheap).
2. في Render: الخدمة ← **Settings** ← **Custom Domains** ← **Add** وأدخل الدومين.
3. عند مسجّل الدومين أضف سجل DNS الذي يعرضه Render (عادة CNAME للنطاق الفرعي
   مثل `chat.example.com`، أو سجلات A/ALIAS للنطاق الرئيسي).
4. انتظر تفعيل شهادة HTTPS — يصدرها Render تلقائياً مجاناً.

## ملاحظات

- المكالمات تحتاج إذن الميكروفون (والكاميرا لمكالمات الفيديو) من المتصفح،
  وتتطلب HTTPS عند النشر (أو localhost عند التجربة المحلية) لعمل `getUserMedia`.
- الجلسات والبيانات محفوظة في `data.json`؛ انسخ الملف احتياطياً إذا جرّبت
  ببيانات تهمّك محلياً.
