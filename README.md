# رسائلي — تطبيق مراسلة ومكالمات بخادم خاص

تطبيق ويب للمراسلة النصية والمكالمات الصوتية والمرئية: تسجيل ودخول باسم مستخدم وكلمة مرور،
دليل مستخدمين، محادثات تُحفظ على الخادم وتُسلَّم لحظياً بين **أجهزة مختلفة** عبر
WebSocket، مع حالة «متصل الآن» وعدّادات غير المقروء وعلامات (أُرسلت / تم التسليم / مقروءة).
الواجهة عربية RTL ومتجاوبة مع الجوال، مع PWA manifest.

## بنية المشروع

```
server.js          الخادم: واجهة ثابتة + REST API + WebSocket على نفس المنفذ
mailer.js          إرسال البريد (SMTP2GO أو Mailjet أو Brevo عبر HTTPS أو SMTP بـ Gmail أو صندوق صادر للاختبار — دون اعتماديات)
store.js           طبقة التخزين (وحدة واحدة — انظر «قاعدة البيانات» أدناه)
public/            الواجهة (index.html + app.js + styles.css + manifest)
test/e2e.mjs       اختبار شامل آلي (npm test)
render.yaml        إعدادات النشر على Render
data/              ملف البيانات data.json (يُنشأ تلقائياً، غير مرفوع لـ Git)
```

- المنفذ: `process.env.PORT` (افتراضي 3000) — الخادم والواجهة على نفس المنفذ والرابط.
- كلمات المرور: مُجزّأة بـ `scrypt` من مكتبة Node المدمجة، وجلسات الدخول رموز عشوائية.

## التشغيل محلياً

```bash
npm install
npm start
```

ثم افتح: http://localhost:3000

للتجربة من جهازين على نفس الشبكة: افتح `http://<IP-جهازك>:3000` من الجوال،
أو افتح متصفحين/نافذتين وسجّل باسمين مختلفين.

## الاختبار الآلي

```bash
npm test
```

يشغّل خادماً مؤقتاً ويتحقق من: التسجيل، رفض الاسم المكرر وكلمة المرور الخاطئة،
الإرسال اللحظي عبر WebSocket، سجل المحادثة، إشعار القراءة، وحفظ رسالة أُرسلت
أثناء غياب المستقبِل وظهورها بعد عودته، إضافة إلى إشارات المكالمات (دعوة/قبول/رفض/
عرض وجواب SDP ومرشحات ICE/إنهاء) وإعادة التفاوض (عرض/جواب ثانٍ) أثناء مكالمة
قائمة وسجلّات المكالمات وحالة «غير متاح» للمستخدم غير المتصل،
ورفع الملفات (مصادقة/أنواع مسموحة/استرجاع البايتات كما هي) ورسائل الصور والصوت
وحذف الرسائل لدى الجميع ولدى طرف واحد، وقواعد الحساب الجديد أدناه، وطول الاسم
(حرف واحد حتى ٢٤) وحساسية حالة الأحرف، والصورة الشخصية، وعرض ملف مستخدم،
وتغيير اسم المستخدم (والاسم المُخلى متاح فوراً للجميع)، ولوحة بيانات المالك،
وأمان الحساب: تغيير كلمة المرور مع إلغاء بقية الجلسات، وربط بريد مؤكد برمز
من ٦ أرقام، واستعادة كلمة السر بالبريد (النقاط البريدية ترجع 503 على خادم
بلا إعداد بريد).

## المكالمات الصوتية والمرئية (WebRTC)

- من ترويسة أي محادثة: زر 📞 لمكالمة صوتية وزر 📹 لمكالمة فيديو، مع واجهة للمكالمة
  الصادرة («جارٍ الاتصال…») والواردة (قبول/رفض مع نغمة رنين) والجارية (مؤقّت مباشر،
  كتم الميكروفون، تشغيل/إيقاف الكاميرا، إنهاء). في مكالمات الفيديو يظهر الطرف الآخر
  بملء الشاشة وفيديوهك صغيراً في الزاوية (Picture-in-Picture).
- **الإشارة (Signaling):** تمر عبر WebSocket الخادم نفسه بين الطرفين فقط بأنواع
  الرسائل: `call_invite` و`call_accept` و`call_reject` و`call_offer` و`call_answer`
  و`call_ice` و`call_end`. الخادم يتتبّع حالة كل مكالمة: إذا كان الطرف الآخر غير
  متصل يرجع للمتصل `call_unavailable`، وإذا كان في مكالمة أخرى يرجع `call_busy`،
  ويُنهي الحالة تلقائياً عند انقطاع اتصال أحد الطرفين.
- **الوسائط نفسها (الصوت/الفيديو) لا تمر عبر الخادم إطلاقاً** — تنتقل مباشرة بين
  المتصفحين (Peer-to-Peer) عبر `RTCPeerConnection`، والخادم لا يخزّن أي SDP أو ICE.
- **اكتشاف العناوين (STUN):** تُستخدم خوادم Google العامة
  (`stun:stun.l.google.com:19302` و`stun:stun1.l.google.com:19302`) لاكتشاف
  العنوان العام خلف NAT.
- **فتح الكاميرا أثناء مكالمة صوتية (ترقية لفيديو):** زر «📷 فتح الكاميرا» ظاهر
  أثناء المكالمات الصوتية أيضاً — يضيف مسار فيديو HD إلى الاتصال القائم (يبقى
  مسار الصوت كما هو) ويعيد التفاوض تلقائياً؛ وعند وصول فيديو الطرف الآخر يتحول
  عرضه لوضع الفيديو. عند تصادم عرضَين متزامنين يُطبَّق تفاوض مهذّب (Perfect
  Negotiation): صاحب الاسم الأكبر معجمياً يتراجع ويجيب. وإن رُفض إذن الكاميرا
  تستمر المكالمة الصوتية كما هي مع رسالة توضيحية.
- **سجل المكالمات:** عند انتهاء أي مكالمة (أو رفضها أو فواتها) يُحفظ سجل واحد في
  سجل المحادثة كرسالة من نوع `kind: "call"` تظهر كصفّ نظامي في المنتصف، مثل
  «📞 مكالمة صوتية — 02:35» أو «📹 مكالمة فيديو فائتة» أو «مكالمة مرفوضة»،
  ويُستخدم كمعاينة للمحادثة إذا كان الأحدث.
- **ملاحظة صادقة عن TURN:** بعض الشبكات الصارمة (NAT متماثل أو جدران نارية
  مؤسسية) قد تمنع الاتصال المباشر بين الطرفين، وعندها تحتاج المكالمة إلى خادم
  **TURN** وسيط لتمرير الوسائط. النسخة الحالية (v1) لا تتضمن TURN — يعمل الاتصال
  على أغلب الشبكات المنزلية وشبكات الجوال، ويمكن إضافة TURN لاحقاً عند الحاجة.

## ميزات إضافية: حذف الرسائل، الوسائط الأصلية، ومخرج صوت المكالمة

- **حذف الرسائل:** بالضغط المطوّل (نحو 600ms) أو النقر باليمين على أي فقاعة رسالة
  تظهر قائمة فيها:
  - «حذف لدى الجميع» (لرسائلك فقط): تختفي الرسالة عن الطرفين وتظهر عندهما
    «🚫 تم حذف هذه الرسالة» — لكن الحذف ليس إتلافاً للمحتوى: يحتفظ مالك
    التطبيق وحده بنسخة كاملة من الرسالة المحذوفة (نصّها وملف وسائطها) في
    لوحة البيانات، موسومةً بأنها محذوفة لدى الجميع، ولا يُفتح ملفها بعد
    الحذف إلا بجلسة المالك نفسه.
  - «حذف لديّ»: تختفي الرسالة من جهازك وسجلّك وحدك، وتبقى عند الطرف الآخر.
  - يُبثّ حدث `message_deleted` عبر WebSocket للطرفين فتتحدث المحادثات المفتوحة
    لحظياً، ولا تُحسب الرسائل المحذوفة أو المخفية في عدّادات «غير المقروء».
- **الوسائط بجودتها الأصلية:** زر 📎 في شريط الإدخال يرسل صوراً وفيديوهات من
  الجهاز، وزر 🎤 يسجّل رسالة صوتية من المتصفح مباشرة (MediaRecorder) مع مؤقّت
  وخيارَي «إلغاء» / «إرسال». **حدّ الرسالة الصوتية دقيقة واحدة (٦٠ ثانية) من زمن
  التسجيل الفعلي**، مع زر «⏸ إيقاف مؤقت / ▶ متابعة» أثناء التسجيل (حيث يدعمه
  المتصفح) — فترات الإيقاف المؤقت لا تُحسب من الدقيقة ولا من مدة الرسالة، وعند
  بلوغ الحد يتوقف التسجيل تلقائياً ويصبح جاهزاً للإرسال أو الإلغاء. تُرفع الملفات عبر `POST /api/upload` (حتى 100MB،
  بأنواع MIME مسموحة فقط) وتُقدَّم عبر `GET /files/:id` مع دعم Range لتنقّل
  الفيديو. **لا يُعاد ترميز أي ملف ولا يُصغَّر ولا يُضغط** — ما يُرفع هو ما يُحفظ
  وما يُسلَّم، بايتاً ببايت.
- **مخرج صوت المكالمة:** أثناء المكالمة زر للتبديل بين «📞 سماعة الهاتف» و
  «🔊 مكبر الصوت» (الافتراضي: سماعة الهاتف للمكالمات الصوتية، والمكبر للفيديو).
  يعتمد على `setSinkId` وقائمة أجهزة الإخراج التي يكشفها المتصفح.
- **ملاحظات صادقة:**
  - ملفات الوسائط تُحفظ على قرص الخادم في `data/uploads/` بجودتها الأصلية،
    وتبقى ما بقي قرص المضيف — وهي نفس ملاحظة ملف `data.json`: على الخطط ذات
    نظام الملفات المؤقت (مثل Render المجاني) تضيع الملفات والبيانات معاً عند
    إعادة التشغيل، وللدوام يلزم قرص دائم أو تخزين خارجي.
  - تبديل السماعة/المكبر يعمل حيث يكشف المتصفح أجهزة الإخراج (مثل Chrome على
    Android والحاسوب)؛ **متصفح Safari على iOS لا يسمح لصفحات الويب بتبديل
    سماعة الأذن** — عندها يظهر تنبيه داخل المكالمة ويتبع الصوت إعدادات الهاتف
    نفسه، وتستمر المكالمة دون انقطاع.

## قواعد الحسابات الجديدة

تُفرض عند **إنشاء الحساب فقط** (`POST /api/register`) — الدخول بالحسابات القائمة
لا يتأثر بأيٍّ منها:

- **اسم المستخدم فريد** (يُرفض التكرار برسالة واضحة)، ويبدأ **بحرف أو رقم**،
  ويمكن أن يحتوي بعد ذلك على حروف وأرقام وعلامات `_` و`.` و`-` فقط، بطول كلي
  من **حرف واحد حتى ٢٤ حرفاً** (اسم مثل `A` أو `7` صالح).
- **حالة الأحرف جزء من الهوية:** الفرادة والدخول بمطابقة دقيقة لحالة الأحرف،
  فـ`omer` و`Omer` و`oMer` أسماء مختلفة يمكن أن تكون حسابات منفصلة، والدخول
  يتطلب كتابة الاسم بنفس حالة الأحرف المسجّلة. (البحث في دليل الأشخاص وحده
  غير حسّاس للحالة لتسهيل إيجاد الناس، دون تأثير على الهوية.)
- **كلمة المرور قوية:** ٤ حروف على الأقل + رقم واحد على الأقل + رمز واحد على
  الأقل (مثل `!` أو `#`)، وترجع رسالة الخطأ بما ينقصها تحديداً. تعرض شاشة
  التسجيل في الواجهة قائمة فحص حية تكتمل أثناء الكتابة.

## الملف الشخصي: الصورة الشخصية وتغيير الاسم

من ترويسة الشاشة الرئيسية، الضغط على صورتك/اسمك يفتح لوحة الملف الشخصي:

- **الصورة الشخصية:** «تغيير الصورة الشخصية» يرفع صورة من جهازك (عبر
  `POST /api/upload` كما هي، دون ضغط) ثم يعيّنها عبر `POST /api/me/avatar`.
  تظهر الصورة دائرية في قائمة المحادثات ودليل الأشخاص وترويسة المحادثة
  وواجهة المكالمة، ومن لا صورة له يظهر حرفه الأول. تعرض الاستجابات الحقل
  `avatar` (رابط `/files/<id>`) في `/api/me` ودليل المستخدمين وقائمة المحادثات.
- **تغيير اسم المستخدم** (`POST /api/me/username`): بنفس قواعد التسجيل
  (حرف واحد حتى ٢٤، يبدأ بحرف أو رقم، فرادة دقيقة لحالة الأحرف). الهوية
  مرتبطة بمعرّف المستخدم لا باسمه، فتبقى الجلسة والرسائل والمحادثات سليمة
  وتظهر بالاسم الجديد عند الجميع فوراً دون إعادة دخول.
- **لا مهلة حجز على الاسم القديم:** بمجرد تغيير الاسم يصبح الاسم المُخلى
  متاحاً فوراً لأي شخص آخر — بالتسجيل أو بتغيير الاسم — دون أي فترة انتظار.
  (حقل `nameReservations` في ملفات البيانات القديمة لم يعد له أي أثر ويُحمَّل
  كما هو للتوافق فقط.)
- **عرض ملفات المستخدمين:** الضغط على صورة أي مستخدم أو اسمه — في دليل
  الأشخاص أو قائمة المحادثات أو ترويسة المحادثة — يفتح لوحة ملفه: صورة
  كبيرة (الضغط عليها يعرض الأصل بحجم كامل داخل التطبيق)، الاسم، حالة
  الاتصال، وأزرار «مراسلة» و«📞 صوت» و«📹 فيديو». تعتمد اللوحة على
  `GET /api/users/:username` الذي يرجع `{ username, avatar, online }`.

## الخصوصية ومنع الالتقاط (مستوى الويب)

حماية الخصوصية: نمنع حفظ الصور من داخل التطبيق ونخفي المحتوى عند تبديل
التطبيقات. ملاحظة: لا يمكن لأي موقع ويب منع لقطات شاشة نظام التشغيل منعاً
كاملاً — الحظر الكامل يحتاج نسخة التطبيق الأصلية (أندرويد/آيفون).

ما يُطبَّق فعلياً في الواجهة:
- منع قائمة السياق (النقر باليمين/اللمس المطوّل) ومنع سحب الصور على وسائط
  المحادثات والصور الشخصية وعارض الصور (`contextmenu` + `draggable=false` +
  `-webkit-touch-callout: none` و`user-select: none`).
- عند إخفاء الصفحة أو تبديل التطبيقات (`visibilitychange`) تُعتَّم الواجهة
  كلها بتمويه (blur 18px) حتى تعود الصفحة مرئية — فتُظهر لقطة مُبدّل
  التطبيقات والتصوير العابر محتوى مموّهاً غير مقروء.
- عارض الصور داخل التطبيق نفسه (لا تبويب جديد) حتى تسري هذه الحماية على
  عرض الصور الشخصية بحجم كامل.

## لوحة بيانات المالك (Admin)

عند ضبط متغير البيئة `ADMIN_USERNAME` على اسم مستخدم قائم (مطابقة دقيقة
لحالة الأحرف) يصبح ذلك الحساب هو «المالك»:

- يرجع `GET /api/me` له الحقل `isAdmin: true`، وتظهر في واجهته زر
  «🗄 لوحة البيانات» يفتح شاشة فيها: نظرة عامة (أعداد المستخدمين والرسائل
  والملفات وحجمها الكلي)، قائمة المستخدمين مع حالات اتصالهم، قائمة
  المحادثات (زوج + عدد الرسائل + معاينة الأخيرة) والضغط على أي محادثة
  يعرض سجلّها كاملاً للقراءة فقط — بكل الأنواع، والرسائل المحذوفة لدى
  الجميع تظهر هنا بمحتواها الأصلي كاملاً مع وسم «محذوفة لدى الجميع» —
  وشبكة الملفات المرفوعة بمالك كل ملف (والملفات المُحتجَزة من رسائل
  محذوفة موسومة «محذوفة — محفوظة للمالك»).
- النقاط: `GET /api/admin/overview` و`/api/admin/users`
  و`/api/admin/conversations` و`/api/admin/messages?a=<اسم>&b=<اسم>`
  و`/api/admin/uploads` — كلها تتطلب جلسة المالك نفسه؛ لغير المالك ترجع
  403، وعند عدم ضبط `ADMIN_USERNAME` أصلاً ترجع 404.
- أمثلة التشغيل: `ADMIN_USERNAME=omer npm start` (مع ضبط `DATA_DIR`/
  `PORT` كما يلزم بيئة النشر).

## البريد والتحقق (Gmail)

ثلاث ميزات حساب تعتمد على البريد الإلكتروني:

- **ربط بريد مؤكد بالحساب:** من لوحة الملف الشخصي «📧 البريد الإلكتروني» —
  يُدخل المستخدم بريده فيُرسَل إليه رمز تأكيد من ٦ أرقام، وبإدخاله يصبح البريد
  «مؤكداً» ومرتبطاً بالحساب (`POST /api/me/email` ثم `POST /api/me/email/verify`).
- **استعادة كلمة السر:** من شاشة الدخول «نسيت كلمة السر؟» — يُرسَل رمز استعادة
  إلى البريد المؤكد، وبه تُعيَّن كلمة سر جديدة (`POST /api/password/forgot` ثم
  `POST /api/password/reset`). طلب الاستعادة يرجع دائماً بنجاح ظاهرياً حتى لا
  يكشف وجود الحساب أو بريده، والتعيين الناجح يُلغي كل جلسات المستخدم.
- **تغيير كلمة السر:** من لوحة الملف الشخصي «🔑 تغيير كلمة السر»
  (`POST /api/me/password`) — يتطلب كلمة السر الحالية، ويفرض قاعدة القوة نفسها
  على الجديدة، ويُبقي جلسة المُغيِّر ويُلغي كل جلساته الأخرى.

رموز البريد: ٦ أرقام، صلاحيتها ١٠ دقائق، تُخزَّن مجزّأة فقط (SHA-256)، تُبطَل
بعد ٥ محاولات خاطئة، وبين كل إرسالين لنفس الغرض مهلة ٦٠ ثانية.

### تفعيل الإرسال الفعلي — إعداد المالك

أولوية وسائل الإرسال في التطبيق: `MAIL_OUTBOX` (للاختبار/التطوير) ←
**SMTP2GO** عند ضبط `SMTP2GO_API_KEY` ← **Mailjet** عند ضبط
`MAILJET_API_KEY` + `MAILJET_API_SECRET` ← **Brevo** عند ضبط
`BREVO_API_KEY` ← **SMTP** عند ضبط `SMTP_USER`/`SMTP_PASS` ← غير ذلك يبقى
البريد معطّلاً.

#### الخيار الأول (المُعتمد حالياً): SMTP2GO عبر HTTPS — تأكيد المُرسِل بالبريد فقط

اختير SMTP2GO كمسار الإرسال المعتمد حالياً: **يؤكّد عنوان المُرسِل عبر رابط
يصل بالبريد الإلكتروني فقط، دون أي تحقق برقم هاتف**، والإرسال عبر HTTPS
(المنفذ 443) فلا يتأثر بحجب منافذ SMTP في بعض بيئات الاستضافة. (اعتُمد بعد
أن أوقف Mailjet الإرسال على الحساب الجديد بانتظار مراجعة الدعم، وتعذّر
إتمام تحقق SMS في Brevo — انظر الخيارين أدناه.)

متغيرات البيئة:

- `SMTP2GO_API_KEY`: مفتاح API من حساب SMTP2GO (له الأولوية على Mailjet
  وBrevo وSMTP متى ضُبط).
- `MAIL_FROM`: بريد المُرسِل الذي أكّدته داخل SMTP2GO (إن لم يُضبط يُستخدم
  `SMTP_USER` بدلاً منه).
- اختياري: `SMTP2GO_API_URL` (الافتراضي `https://api.smtp2go.com/v3/email/send`).

خطوات الإعداد (الخطة المجانية تكفي — ١٠٠٠ رسالة شهرياً، أكثر من حاجة رموز
التحقق):

1. أنشئ حساباً مجانياً في [SMTP2GO](https://www.smtp2go.com).
2. أكّد بريدك كمُرسِل: من **Settings ← Verified Senders** أضف عنوان البريد،
   ثم افتح رابط التأكيد في الرسالة التي تصلك على ذلك البريد.
3. أنشئ مفتاح API: من **Settings ← API Keys** أنشئ مفتاحاً جديداً وانسخه.
4. في Railway: افتح خدمة التطبيق ← **Variables** وأضف `SMTP2GO_API_KEY`
   و`MAIL_FROM` (بريد المُرسِل المؤكد)، ثم أعد النشر/التشغيل.

#### الخيار الثاني: SMTP عبر Gmail

إرسال البريد عبر SMTP لا يعمل إلا إذا ضُبطت متغيرات البيئة التالية على الخادم:

- `SMTP_USER`: عنوان Gmail الذي سيُرسل منه التطبيق (مثال: `myapp@gmail.com`)
- `SMTP_PASS`: **كلمة سر تطبيق (App Password)** لذلك الحساب — ليست كلمة سر
  Gmail العادية
- اختياري: `SMTP_HOST` (الافتراضي `smtp.gmail.com`) و`SMTP_PORT` (الافتراضي
  `465` بـ TLS ضمني؛ اضبط `587` لاستخدام STARTTLS)

إنشاء كلمة سر التطبيقات في Gmail:

1. افتح حساب Google ← **الأمان (Security)**.
2. فعّل **التحقق بخطوتين (2-Step Verification)** إن لم يكن مفعّلاً (كلمات سر
   التطبيقات لا تظهر بدونه).
3. من الأمان ← **كلمات سر التطبيقات (App passwords)**: أنشئ كلمة سر جديدة
   وانسخها (١٦ حرفاً تُعرض مرة واحدة).
4. في Railway: افتح خدمة التطبيق ← **Variables** وأضف `SMTP_USER` و`SMTP_PASS`
   بالقيمتين أعلاه، ثم أعد النشر/التشغيل.

#### الخيار الثالث: Mailjet عبر HTTPS — تأكيد المُرسِل بالبريد فقط

اختير Mailjet لأنه **يؤكّد عنوان المُرسِل عبر رابط يصل بالبريد الإلكتروني
فقط، دون أي تحقق برقم هاتف** — فإنشاء مفاتيح API فيه متاح مباشرة بعد تأكيد
المُرسِل (في Brevo تعذّر إتمام إنشاء المفتاح لأن التحقق برسالة SMS لم يصل
إلى هاتف المالك). والإرسال أيضاً عبر HTTPS (المنفذ 443) فلا يتأثر بحجب
منافذ SMTP الموصوف في خيار Brevo أدناه.

متغيرات البيئة:

- `MAILJET_API_KEY` + `MAILJET_API_SECRET`: مفتاح API وسرّه من حساب Mailjet
  (لهما الأولوية على Brevo وSMTP متى ضُبطا معاً، وتسبقهما SMTP2GO متى ضُبط
  مفتاحها).
- `MAIL_FROM`: بريد المُرسِل الذي أكّدته داخل Mailjet (إن لم يُضبط يُستخدم
  `SMTP_USER` بدلاً منه).
- اختياري: `MAILJET_API_URL` (الافتراضي `https://api.mailjet.com/v3.1/send`).

خطوات الإعداد (الخطة المجانية تكفي — ٦٠٠٠ رسالة شهرياً بحدّ ٢٠٠ رسالة
يومياً، أكثر من حاجة رموز التحقق):

1. أنشئ حساباً مجانياً في [Mailjet](https://www.mailjet.com).
2. أكّد بريدك كمُرسِل: من **Account settings ← Senders & Domains** (أو
   **Senders**) أضف عنوان البريد، ثم افتح رابط التأكيد في الرسالة التي تصلك
   على ذلك البريد.
3. انسخ بيانات API: من **Account settings ← API Key Management** خذ
   **API Key** و**Secret Key** الخاصين بحسابك.
4. في Railway: افتح خدمة التطبيق ← **Variables** وأضف `MAILJET_API_KEY`
   و`MAILJET_API_SECRET` و`MAIL_FROM` (بريد المُرسِل المؤكد)، ثم أعد
   النشر/التشغيل.

#### الخيار الرابع: Brevo عبر HTTPS

بعض بيئات الاستضافة — منها خطة Railway التجريبية — **تحجب الاتصالات الصادرة
إلى منافذ SMTP (465 و587)** لمنع الرسائل المزعجة، فتنتهي مهلة الاتصال بخوادم
Gmail قبل أي مصادقة مهما كانت بيانات الاعتماد صحيحة. الإرسال عبر واجهة Brevo
البرمجية يسير على HTTPS (المنفذ 443) فلا يتأثر بهذا الحجب إطلاقاً.

متغيرات البيئة:

- `BREVO_API_KEY`: مفتاح API من حساب Brevo (له الأولوية على SMTP متى ضُبط).
- `MAIL_FROM`: بريد المُرسِل الذي أكّدته داخل Brevo (إن لم يُضبط يُستخدم
  `SMTP_USER` بدلاً منه).
- اختياري: `BREVO_API_URL` (الافتراضي `https://api.brevo.com/v3/smtp/email`).

خطوات الإعداد (الخطة المجانية تكفي — ٣٠٠ رسالة يومياً، أكثر من حاجة رموز
التحقق):

1. أنشئ حساباً مجانياً في [Brevo](https://www.brevo.com).
2. من **الإعدادات ← المُرسِلون والمجالات (Senders & IPs)**: أضف بريدك كمُرسِل
   وأكّده من رسالة التأكيد التي تصلك.
3. من **الإعدادات ← مفاتيح API (API Keys)**: أنشئ مفتاحاً جديداً وانسخه (يُعرض
   مرة واحدة).
4. في Railway: افتح خدمة التطبيق ← **Variables** وأضف `BREVO_API_KEY`
   و`MAIL_FROM` (بريد المُرسِل المؤكد)، ثم أعد النشر/التشغيل.

بدون ضبط أي وسيلة إرسال (لا SMTP2GO ولا Mailjet ولا Brevo ولا SMTP) يبقى الإرسال معطّلاً: ترجع
النقاط البريد 503 «إرسال البريد غير مفعّل بعد»، وتعرض الواجهة للمستخدم ملاحظة
«إرسال البريد غير مفعّل بعد — بانتظار إعداد المالك لحساب Gmail».
(للتطوير والاختبار الآلي يمكن ضبط `MAIL_OUTBOX` على مسار ملف: تُكتب فيه كل
رسالة كسطر JSON بدل إرسالها فعلياً.)

## النشر على Render عبر GitHub (خطوة بخطوة)

1. أنشئ حساباً على GitHub وارفع هذا المشروع إلى مستودع (Repository) جديد.
2. أنشئ حساباً على Render.com وسجّل الدخول.
3. من لوحة Render: **New +** ← **Blueprint** ← اختر المستودع — سيقرأ Render ملف
   `render.yaml` وينشئ خدمة الويب تلقائياً. (أو يدوياً: **New +** ← **Web Service**
   ← ربط المستودع ← Build Command: `npm install` ← Start Command: `npm start`
   ← Plan: Free.)
4. انتظر انتهاء أول نشر، وسيعطيك Render رابطاً مثل:
   `https://messages-app.onrender.com`
5. افتح الرابط من أي جهاز، أنشئ حساباً، وجرّب المراسلة بين جهازين مختلفين.

### حدود الخطة المجانية في Render — مهم

- **الخادم ينام** بعد 15 دقيقة بدون حركة، وأول طلب بعده يحتاج نحو دقيقة ليصحو.
- **نظام الملفات مؤقت (ephemeral):** أي ملفات تُكتب أثناء التشغيل — ومنها
  `data/data.json` الذي يحمل المستخدمين والرسائل — **تُمسح عند كل إعادة تشغيل
  أو إعادة نشر**. أي أن البيانات على الخطة المجانية مؤقتة وتناسب التجربة فقط.

### لجعل البيانات دائمة (عند الإطلاق الفعلي)

اختر واحداً:
- الترقية لخطة مدفوعة في Render + إضافة **Persistent Disk** وتركيبه على مجلد
  البيانات وضبط `DATA_DIR` عليه، أو
- الانتقال لقاعدة بيانات **Postgres**: طبقة التخزين كلها في `store.js`،
  فاستبدال هذه الوحدة وحدها بنسخة Postgres يكفي دون تغيير بقية الخادم.

## إضافة دومين خاص لاحقاً

1. اشترِ الدومين من أي مسجّل (مثل Cloudflare Registrar أو Namecheap).
2. في Render: الخدمة ← **Settings** ← **Custom Domains** ← **Add** وأدخل الدومين.
3. عند مسجّل الدومين أضف سجل DNS الذي يعرضه Render (عادة CNAME للنطاق الفرعي
   مثل `chat.example.com`، أو سجلات A/ALIAS للنطاق الرئيسي).
4. انتظر تفعيل شهادة HTTPS — يصدرها Render تلقائياً مجاناً.

## ملاحظات

- المكالمات تحتاج إذن الميكروفون (والكاميرا لمكالمات الفيديو) من المتصفح،
  وتتطلب HTTPS عند النشر (أو localhost عند التجربة المحلية) لعمل `getUserMedia`.
- الجلسات والبيانات محفوظة في `data.json`؛ انسخ الملف احتياطياً إذا جرّبت
  ببيانات تهمّك محلياً.
